Customization

Adapt Nexaline without forking it

Override public semantic tokens on the narrowest useful scope. Keep component selectors and generated source files unchanged so upgrades remain predictable.

Semantic tokens

Components consume variables prefixed with --nx-. Prefer semantic tokens such as primary, surface, text, border, focus, spacing, radius, and control size over palette values tied to one color.

PurposePublic token
Primary action--nx-color-primary, --nx-color-primary-hover, --nx-color-on-primary
Surfaces--nx-color-surface, --nx-color-surface-muted, --nx-color-surface-raised
Content--nx-color-text, --nx-color-text-muted, --nx-color-border
Keyboard focus--nx-color-focus
Shape--nx-radius-sm, --nx-radius-md, --nx-radius-lg
Controls--nx-control-height, --nx-control-pad
Contrast remains your responsibility. Test text, controls, focus indicators, disabled states, and status colors after overriding any token.

Scope brand overrides

Apply a brand globally on :root, or scope it to a product area, tenant, or embedded widget.

.acme-portal {
  --nx-color-primary: #6d28d9;
  --nx-color-primary-hover: #5b21b6;
  --nx-color-on-primary: #fff;
  --nx-color-focus: #7c3aed;
  --nx-radius-md: .5rem;
}

Light, dark, and system color modes

Set the theme on the document root or a containing scope. Server-render the correct value when possible to avoid a flash before JavaScript restores a saved preference.

<html data-nx-theme="light">
<html data-nx-theme="dark">
<html data-nx-theme="system">

system follows prefers-color-scheme. A custom dark brand must override the same semantic tokens within its dark-theme scope.

Control density

Compact density changes control height and padding without shrinking typography or removing accessible names. Use it for data-dense desktop tools, not as a substitute for responsive design.

<section data-nx-density="compact">
  <button class="nx-btn" type="button">Compact action</button>
</section>
Default
Compact

Cascade layers and override order

Nexaline declares five stable layers in this order:

@layer nx-reset, nx-base, nx-layout, nx-components, nx-utilities;

Unlayered application CSS wins over layered framework CSS at equal origin. If your application also uses layers, declare its layer after Nexaline and keep component customization token-based.

@layer nx-reset, nx-base, nx-layout, nx-components, nx-utilities, app;

@layer app {
  .billing-summary { --nx-stack-gap: var(--nx-space-6); }
}

Aggregate or no-reset CSS

Use nexaline-ui/css for a complete setup. Use nexaline-ui/no-reset.css when the host application already controls margins, typography inheritance, media sizing, and global box-sizing.

import 'nexaline-ui/css'          // complete distribution
import 'nexaline-ui/no-reset.css' // omit Nexaline's reset layer

Do not import both files. The no-reset build still includes tokens, layout, components, and utilities.

RTL and logical properties

Set an accurate document direction. Nexaline layouts use logical properties, and enhanced tabs account for direction when processing horizontal arrow keys.

<html lang="ar" dir="rtl">

Application CSS should prefer margin-inline, padding-inline, and inset-inline-start over left/right properties.

Reduced motion

Nexaline reduces animation and transition durations when the user requests reduced motion. Preserve that behavior in application animation and avoid making motion the only way to communicate state.

@media (prefers-reduced-motion: reduce) {
  .app-animation { animation: none; }
}
