Getting started

Install Nexaline UI

Choose one installation path, load the CSS, and add JavaScript only when your page uses enhanced behavior such as dialogs, drawers, tabs, dropdowns, or toasts.

Package manager

Install the aggregate package for the complete compiled CSS and JavaScript distribution. The beta tag follows the current public beta.

npm install nexaline-ui@beta
pnpm add nexaline-ui@beta

Import the stylesheet and initialize behavior from your application entry point.

import 'nexaline-ui/css'
import { init } from 'nexaline-ui'

const lifecycle = init(document)
// Call lifecycle.destroy() before removing the initialized root.

CDN without a build step

Use an exact version in production so later beta releases cannot change an existing page unexpectedly.

<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/nexaline-ui@0.1.0-beta.1/dist/nexaline.min.css">
<script src="https://cdn.jsdelivr.net/npm/nexaline-ui@0.1.0-beta.1/dist/nexaline.min.js" defer></script>
Production note: self-host the files or add verified Subresource Integrity values when your deployment policy requires asset pinning beyond the exact package version.

Starter template

This no-build document contains the required metadata and uses semantic HTML before adding framework classes.

<!doctype html>
<html lang="en" dir="ltr" data-nx-theme="light">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Nexaline starter</title>
    <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/nexaline-ui@0.1.0-beta.1/dist/nexaline.min.css">
  </head>
  <body>
    <main class="nx-container nx-stack nx-gap-4">
      <h1>Hello, Nexaline UI!</h1>
      <button class="nx-btn nx-btn--primary" type="button">Continue</button>
    </main>
    <script src="https://cdn.jsdelivr.net/npm/nexaline-ui@0.1.0-beta.1/dist/nexaline.min.js" defer></script>
  </body>
</html>

Optional JavaScript

Most styling, layout, forms, alerts, badges, tables, and progress indicators require no JavaScript. Enhanced components use semantic markup plus explicit data-nx-* hooks.

The aggregate browser file exposes NexalineUI; call NexalineUI.init(document) after it loads. Module consumers can import individual constructors or call init(root) after inserting dynamic content.

Review initialization, lifecycle, constructors, and events.

Required global setup

HTML5 doctype
Use <!doctype html> so browsers render in standards mode.
Responsive viewport
Use width=device-width, initial-scale=1 for mobile layout and zoom behavior.
Box sizing and reset
The aggregate stylesheet includes Nexaline’s reset and border-box sizing. Use nexaline-ui/no-reset.css when integrating into an application that owns those global rules.
Direction and language
Set accurate lang and dir attributes on the document root. Nexaline uses logical properties for LTR and RTL.
Theme
Set data-nx-theme="light", dark, or system before paint when possible.

Browser and accessibility support

The supported floor is Chrome and Edge 111+, Firefox 114+, and Safari and iOS 16.4+. Progressive HTML and CSS remain usable when JavaScript is unavailable.

Nexaline provides accessible component behavior, but application authors remain responsible for semantic content, labels, validation messages, reading order, and testing their complete user flows.
