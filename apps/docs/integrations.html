Integrations

Use the same contracts in every rendering stack

Nexaline has no framework runtime dependency. Render semantic HTML on the server or client, load one deliberate CSS entry, and initialize enhanced behavior only where needed.

Choose an asset path

ApplicationRecommended pathRuntime requirement
Bundled JavaScriptImport nexaline-ui/css and ESM exportsNode only during development/build
Plain HTML or PHPSelf-host compiled CSS and browser JSNone
CodeIgniter or LaravelPublish compiled assets to the public directoryPHP framework only

Do not combine the aggregate stylesheet with modular core/components styles in the same page; that duplicates rules.

Bundlers and package exports

import 'nexaline-ui/css'
import { init } from 'nexaline-ui'

const lifecycle = init(document)

// On application teardown:
lifecycle.destroy()

The aggregate package publishes ESM, CommonJS, browser, type, and CSS entries. Smaller applications can combine @nexaline-ui/core, @nexaline-ui/components, and @nexaline-ui/js deliberately.

CSS retention: package metadata marks stylesheet imports as side effects so production bundlers keep them.

Plain HTML

<link rel="stylesheet" href="/assets/nexaline.min.css">
<script src="/assets/nexaline.min.js" defer></script>
<script>
  window.addEventListener('DOMContentLoaded', () => {
    window.nexalineLifecycle = NexalineUI.init(document)
  })
</script>

Use a relative or root-relative asset URL that matches the deployment base. The browser bundle exposes the global API but requires an explicit init(document) call.

Plain PHP

<label class="nx-label" for="email">Email</label>
<input class="nx-input" id="email" name="email" type="email"
  value="<?= htmlspecialchars($email, ENT_QUOTES, 'UTF-8') ?>">

Nexaline does not change escaping, CSRF, validation, or authorization rules. Escape values for their output context and let the application own request processing.

CodeIgniter 4

<?= form_open('/customers') ?>
  <?= csrf_field() ?>
  <label class="nx-label" for="ci-email">Email</label>
  <input class="nx-input" id="ci-email" name="email" type="email"
    aria-describedby="ci-email-error"
    <?= validation_show_error('email') ? 'aria-invalid="true"' : '' ?>>
  <?php if (validation_show_error('email')): ?>
    <p class="nx-field__error" id="ci-email-error">
      <?= esc(validation_show_error('email')) ?>
    </p>
  <?php endif ?>
  <button class="nx-btn nx-btn--primary">Save customer</button>
<?= form_close() ?>

Copy compiled assets into public/assets, enable the form and CSRF helpers, and render validation text only when it exists.

Laravel Blade

<form method="POST" action="/customers">
  @csrf
  <label class="nx-label" for="laravel-email">Email</label>
  <input class="nx-input" id="laravel-email" name="email" type="email"
    value="{{ old('email') }}" aria-describedby="laravel-email-error"
    @error('email') aria-invalid="true" @enderror>
  @error('email')
    <p class="nx-field__error" id="laravel-email-error">{{ $message }}</p>
  @enderror
  <button class="nx-btn nx-btn--primary">Save customer</button>
</form>

Use either Vite package imports or public compiled assets. Preserve old input intentionally and keep framework validation messages connected to their controls.

Initialize dynamically inserted markup

const root = document.querySelector('#partial-root')
root.innerHTML = response.html
const partial = NexalineUI.init(root)

// Before replacing the partial again:
partial.destroy()

Server navigation that performs a full page load starts a new document. Partial-page systems must initialize the inserted stable root and destroy its lifecycle before replacement.

Optional Lucide adapter

import { CircleCheckBig } from '@lucide/icons'
import { createLucideIcon } from '@nexaline-ui/icons-lucide'

status.prepend(createLucideIcon(CircleCheckBig, {
  decorative: false,
  label: 'Complete'
}))

Nexaline does not bundle an icon set. Decorative icons are hidden from assistive technology. Informative icons require a non-empty label, and an icon never names its parent button automatically.
