Validate clearly and preserve native behavior

Nexaline styles native controls and validation states. Your application owns constraints, messages, validation timing, submission, and server-error reconciliation.

Build every field from explicit relationships

<div class="nx-field">
  <label class="nx-label" for="email">Email</label>
  <input class="nx-input" id="email" type="email"
    autocomplete="email" aria-describedby="email-help" required>
  <p class="nx-field__help" id="email-help">Used for account notices.</p>
</div>
  • A visible label identifies the control.
  • aria-describedby references persistent help and visible errors.
  • Native types, required, patterns, and autocomplete tokens retain browser behavior.
  • Placeholder text is an example, not a replacement for a label.

Group related choices with fieldset and legend

Notification frequency

Checkboxes select independent values. Radios select one value from a named group. A switch changes an immediate on/off setting and retains a visible label.

Disabled and readonly are different states

Readonly values remain focusable and are submitted.

Disabled values are unavailable and are not submitted.

Expose validation in text and programmatic state

  1. Validate on submit; optionally revalidate a field after its first failure.
  2. Set aria-invalid="true" only when the current value is invalid.
  3. Reveal specific text and add its ID to aria-describedby.
  4. For multiple failures, focus a summary containing links to each invalid field.
  5. Do not rely on border color, icons, or toast messages alone.

    Choose validation timing deliberately

    On submit
    Always provide a complete result and move focus to the error summary or first invalid field.
    On blur
    Useful after a user has interacted, but avoid interrupting unfinished input.
    On input
    Use to clear or update an existing error, not to announce an error on every keystroke.

    Merge server errors into the same contract

    After an unsuccessful response, render server messages beside their controls, synchronize aria-invalid and aria-describedby, rebuild the error summary, and focus it. Preserve entered values unless security or privacy requires clearing them.
