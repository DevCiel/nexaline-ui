Build with Nexaline UI

Everything here is rendered with the same source and compiled into the same static documentation build as the framework examples.

Installation and compiled usage

For no-build usage, copy the compiled assets to a public directory. A Node.js server is not needed at runtime.

<link rel="stylesheet" href="/assets/nexaline.min.css">
<script src="/assets/nexaline.min.js" defer></script>

Package consumers use import { Dialog, init } from 'nexaline-ui' and import nexaline-ui/css. Package names remain provisional until registry availability is checked.

Browser support: Chrome and Edge 111+, Firefox 114+, and Safari 16.4+. Progressive HTML/CSS remains usable if JavaScript is unavailable.

Tokens and themes

Semantic variables such as --nx-color-primary, --nx-color-surface, --nx-color-text, --nx-space-4, and --nx-radius-md are the stable customization surface. See the complete customization guide for scoped brands, density, layers, reset choices, RTL, and motion.

:root {
  --nx-color-primary: #6d28d9;
  --nx-color-primary-hover: #5b21b6;
  --nx-radius-md: .5rem;
}

Choose data-nx-theme="light", dark, or system on the root element. Set data-nx-density="compact" when denser controls are appropriate. Server-render the theme attribute to prevent flash under strict CSP.

Layout and bounded utilities

Containers, twelve-column grids, stacks, and clusters use logical properties. Public responsive breakpoints are 48rem and 64rem. See the complete layout and utility guide for live grid examples and the bounded class reference.

Utility output has deterministic source order; conflicting class order in HTML does not determine the winner. Arbitrary values, selectors, and an on-demand scanner are deliberately absent.

JavaScript APIs and events

Use individual constructors or init(root). Repeated initialization shares ownership safely. Initialize inserted fragments explicitly and destroy the returned handle when removing them. See the complete JavaScript API and events guide.

import { init } from 'nexaline-ui';
const lifecycle = init(document);
// Later: lifecycle.destroy();

Cancelable events are nx:beforeopen, nx:beforeclose, and nx:beforechange. Completion events are nx:open, nx:close, and nx:change. Event detail contains the component and trigger.

Accessibility, reduced motion, and RTL

Use semantic elements and visible labels first. Dialogs and drawers manage focus and Escape; tabs, accordions, and menus implement their expected arrow-key models. Automated axe checks supplement manual screen-reader and keyboard review.

Set dir="rtl" on the document root. Logical properties mirror layouts and JavaScript tab navigation accounts for direction. Motion collapses under prefers-reduced-motion: reduce.

Troubleshooting

A component does not open
Confirm the target ID exists, the data attribute is correct, and dynamic markup was passed to init(fragment).
Styles disappear after bundling
Import a CSS entry explicitly. Package metadata marks CSS as a side effect.
Application styles lose
Place application rules in a later layer or leave them unlayered. Avoid relying on HTML class order.
The theme flashes
Render the correct root theme on the server or run an allowed external/nonce-bearing preference bootstrap before CSS paints.
RTL looks incomplete
Set direction at the document root and replace application-owned physical margins with logical properties.

Migration policy and changelog

Before 1.0, APIs are experimental. Breaking beta changes receive a changelog entry describing renamed classes, attributes, events, tokens, or methods and the direct replacement. Deprecations should remain for at least one beta where practical.

The current 0.1.0-beta.1 foundation includes tokens, layouts, bounded utilities, the initial component catalogue, accessible JavaScript lifecycles, modular distribution, integration fixtures, and static documentation. See the repository CHANGELOG.md for the authoritative record.
