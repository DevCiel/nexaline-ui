Layout and utilities

Compose predictable responsive layouts

Nexaline provides a small layout vocabulary and a bounded generated utility set. Every public class is shipped ahead of time; there is no runtime scanner or arbitrary-value syntax.

Containers

.nx-container centers content within --nx-container and preserves responsive gutters. .nx-container-fluid spans the available inline size while keeping those gutters.

<main class="nx-container">Centered content</main>
<section class="nx-container-fluid">Full-width content</section>
Container content respects the current writing direction.

Twelve-column grid

.nx-grid creates twelve equal tracks. Columns span the full grid by default and can take 4, 6, 8, or 12 tracks. Medium responsive spans begin at 48rem.

<div class="nx-grid">
  <aside class="nx-col-12 md:nx-col-4">Sidebar</aside>
  <article class="nx-col-12 md:nx-col-8">Content</article>
</div>
4 columns
8 columns

Override --nx-grid-gap on a grid instance when the default spacing token is not appropriate.

Stack and cluster

A stack arranges children vertically. A cluster arranges and wraps related inline actions. Both accept scoped gap tokens.

<div class="nx-stack" style="--nx-stack-gap:var(--nx-space-6)">...</div>
<div class="nx-cluster" style="--nx-cluster-gap:var(--nx-space-2)">...</div>

HTML class order does not set priority

Generated utility rules have deterministic stylesheet order. Reordering conflicting classes in HTML does not change which declaration wins.

<div class="nx-block nx-hidden">Hidden</div>
<div class="nx-hidden nx-block">Also hidden</div>

Avoid conflicting utilities. Use one class for a property at each breakpoint or write an application-specific rule.

Logical spacing works in LTR and RTL

nx-px-4 uses padding-inline; vertical margin helpers use block directions. Containers, grid, stacks, and clusters therefore adapt without duplicate left/right utilities.

Intentional limits

  • No arbitrary values such as nx-w-[37px].
  • No consumer-source scanner or generated-on-demand classes.
  • No responsive variant exists unless it is listed above.
  • Breakpoints are build-time framework values, not runtime CSS variables.
  • Use component tokens or application CSS when the bounded utilities do not express the design.
